Hard Decisions
SSE over polling

A 2,000–3,500 token BRD can't wait for a full response. Server-Sent Events stream section-by-section from the Anthropic SDK through a Next.js API route to the client, so the UI updates incrementally as content arrives.

Real-time section parser

Claude generates in free-form markdown, not JSON. The parser buffers the streaming token stream and routes content to the correct section bucket by watching for heading patterns — tight enough to work reliably, loose enough to fail gracefully.

Resolve Mode two-pass architecture

The second pass receives original input + first-pass BRD + extracted questions + user answers together — not just the answers appended to a new prompt. This preserves continuity so the refinement is a genuine upgrade, not a restart.

The Problem

Product managers and Scrum Masters spend hours each sprint manually computing metrics from JIRA exports, copying numbers into slide decks, and writing status updates. Existing JIRA dashboards show raw numbers — but don't score them, don't detect patterns, and don't tell you what to do next. This skill automates the full flow.

Key Product Decisions

Why absolute benchmarks, not relative normalization

The original health score used current / max_historical × 100. That's vanity math — a consistently bad team scores "good." v3 uses absolute industry benchmarks: CV < 0.15 for velocity stability, <7 day cycle time, 85% reliability target. A bad team scores low regardless of their own history.

Goal presets over equal weights

Replaced the Equal/Custom toggle with intentional goal presets — Predictability (reliability-heavy), Speed (cycle time-heavy), Output (velocity-heavy), Custom (drag-to-reorder). Different teams optimize for different things. The dashboard makes that explicit.

Prescriptive insights over descriptive ones

Early version said "velocity is in freefall." That's obvious — every chart already shows it. v3 detects spillover (same ticket key across multiple sprints), flags assignee load imbalance, and roots each insight in cause + action, not just observation.

Drag-to-reorder over 4 dropdown selectors

The original Custom mode used 4 dropdowns to set priority. Drag-to-reorder communicates the ranking relationship more intuitively and maps directly to how PMs think about trade-offs — first matters most.

Design Rationale

The 3×3 grid places the health score ring at center — the single most important number — with charts in the four corners and KPI cards at cardinal positions. This creates a natural visual hierarchy: eye goes to center, radiates outward to supporting data. Red flag strip at the top ensures critical alerts are never buried.

Design language follows JIRA, Linear, and Slack — tools agile teams already live in. Dark surface, blue primary, amber health states. No framework — single self-contained JSX file, no build step.

Evaluation Methodology

Tested using a structured eval harness across 3 personas: formal quarterly reviewer, casual Scrum Master, and user with nonstandard JIRA column names. Each run scored 13 assertions covering output structure, circular progress ring rendering, goal preset behavior, spillover detection, and localStorage compliance.
